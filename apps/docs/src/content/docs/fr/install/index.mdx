<InstallPath id="compose">

<Need>
Docker avec le plugin Compose, et un terminal. Testé avec 1 Go de RAM et un cœur de CPU ; Kept et
sa base de données en utilisent environ 200–400 Mo ([ce qui a été testé](/fr/install/hardware/)).
</Need>

<Steps>

1. **Téléchargez `compose.yaml`** dans un dossier à lui : Kept et sa base de données dans un seul
   fichier, sans copie du dépôt et sans mot de passe à créer.

   <Code code={commands.compose.download} lang="sh" />

2. **Écrivez `.env`.** `init` demande l’adresse à laquelle vous ouvrirez Kept, comme
   `http://kept.home.arpa:8080`. Préférez un nom à une adresse IP : les étiquettes imprimées la
   portent.

   <Code code={commands.compose.init} lang="sh" />

   <See>
   <Code code={printed.init} lang="text" />
   </See>

3. **Démarrez-le.** La base de données démarre, deux services à exécution unique créent ses
   identifiants et appliquent les migrations, puis Kept démarre sur le port 8080.

   <Code code={commands.compose.start} lang="sh" />

   <See>
   À l’adresse, la page **Saisissez le code de configuration** de Kept.
   </See>

4. **Configurez-le.** Saisissez le code qu’`init` a affiché et créez le premier compte : il devient
   l’administrateur de l’instance.

5. **Gardez les clés.** Imprimez le kit de récupération et gardez-le ailleurs que sur ce serveur,
   par exemple dans un gestionnaire de mots de passe. Une sauvegarde ne restaure les valeurs
   secrètes qu’avec ces clés.

   <Code code={commands.compose.recoveryKit} lang="sh" />

   <See>
   Un texte qui commence par `KEPT RECOVERY KIT`.
   </See>

</Steps>

<Aside title="Windows">
Dans PowerShell, tapez `curl.exe` là où les étapes disent `curl`, et lancez `mkdir kept` et
`cd kept` l’un après l’autre. Ou lancez toutes les étapes dans WSL.
</Aside>

Chaque étape en détail, avec Caddy pour HTTPS et Ollama pour l’IA locale :
[Installer avec Docker Compose](/fr/install/compose/).

## Quelque chose ne marche pas ?

- **Le conteneur redémarre sans cesse.** Lisez son journal : `docker compose logs kept`. Kept
  vérifie ses réglages avant de démarrer et s’arrête sur une ligne qui nomme le premier problème,
  comme `kept: invalid environment: KEPT_PUBLIC_URL` (lancez `docker compose run --rm init`). Si
  `docker compose up -d` s’arrête à `bootstrap`, `docker compose logs bootstrap` dit pourquoi. Avec
  moins de 1 Go de mémoire, une sauvegarde peut en manquer et Docker redémarre Kept
  ([ce dont il a besoin](/fr/install/hardware/)).
  [Plus](/fr/admin/troubleshooting/#kept-sarrête-au-démarrage-avec-kept-invalid-environment--ou-une-autre-ligne-kept)
- **Le port est déjà pris.** Kept utilise le port 8080 de l’hôte. Relancez
  `docker compose run --rm init` avec une adresse `http://` sur un port libre : il écrit l’adresse
  et le port (`KEPT_HTTP_PORT`) dans `.env`. Puis `docker compose up -d`. Dans l’application Home
  Assistant, changez le port sous **Configuration → Réseau** et réglez **L’adresse de Kept** en
  conséquence.
  [Plus](/fr/install/compose/#1-écrire-env)
- **Permission refusée.** Kept tourne avec l’utilisateur 10001 sur un système de fichiers en
  lecture seule, donc un dossier que vous y montez, comme un répertoire de sauvegarde, doit
  appartenir à l’uid 10001. `init` écrit `.env` dans le dossier d’où vous le lancez : lancez-le
  dans un dossier qui vous appartient.
  [Plus](/fr/admin/troubleshooting/#les-sauvegardes-ne-sexécutent-pas-ou-lalerte--sauvegarde-périmée--se-déclenche)
- **Les autres appareils ne l’ouvrent pas.** `localhost` ne s’ouvre que sur cette machine. Utilisez
  un nom que les autres appareils trouvent, défini dans le DNS de votre routeur ou dans le fichier
  hosts de chaque appareil, et relancez `init` avec lui. Si Kept dit « Ce Kept est configuré pour
  *adresse*. Ouvrez-le à cette adresse. », ouvrez-le exactement à cette adresse, ou ajoutez l’autre
  dans `KEPT_EXTRA_ADDRESSES` ([plusieurs adresses](/fr/install/home-network/#plusieurs-adresses)).
  [Plus](/fr/admin/troubleshooting/#-ce-kept-est-configuré-pour---ou--la-requête-ne-provient-pas-de-ce-site-)
- **Une erreur 502 du proxy inverse.** Kept parle en HTTP simple sur le port 8080 : faites pointer
  le proxy vers `http://`, pas `https://`, sur ce port
  ([derrière un proxy inverse](/fr/install/reverse-proxy/)). Kept ne démarre qu’une fois `migrate`
  terminé ; en cas d’échec, `docker compose logs migrate` dit pourquoi.
  [Plus](/fr/admin/troubleshooting/#kept-ne-démarre-pas-après-une-mise-à-niveau-et-migrate-sest-terminé-avec-une-erreur)

Tout le reste : [Dépannage](/fr/admin/troubleshooting/).

## Aller plus loin

- **HTTPS :** la caméra, l’installation de l’application, les notifications push et la position en
  ont besoin. [Activez le protocole HTTPS pour Kept](/fr/install/https/), ou
  [Kept sur un réseau domestique](/fr/install/home-network/) pour ce qui marche sans.
- **L’assistant :** posez vos questions en langage courant, avec votre propre fournisseur d’IA ;
  Kept fonctionne sans. [Fournisseurs d’IA](/fr/users/ai-providers/), et
  [Connecter un client IA (MCP)](/fr/users/mcp-clients/).
- **Sauvegardes :** chaque nuit et chiffrées, vers un répertoire, S3 ou SFTP.
  [Sauvegardes](/fr/admin/backups/).
- **Courriel :** réinitialisations de mot de passe, invitations et rappels par courriel, avec
  `KEPT_SMTP_URL` et `KEPT_SMTP_FROM`. [Courriel, push et le flux calendrier](/fr/admin/notifications/).
- **Home Assistant :** l’intégration amène ce qui arrive à échéance dans les tableaux de bord et
  les automatisations. [Home Assistant](/fr/users/home-assistant/).

## Mises à jour

- **Docker Compose :** mettez la nouvelle version dans `KEPT_IMAGE` de `.env`, puis :

  <Code code={commands.compose.update} lang="sh" />

  Une version qui change `compose.yaml` le dit dans ses notes : téléchargez son fichier par-dessus
  le vôtre.
- **Depuis les sources :**

  <Code code={commands.source.update} lang="sh" />

- **Kubernetes :** chaque version publie un chart de la même version, et ses migrations
  s’exécutent dans un Job avant que la nouvelle version ne serve.
- **Proxmox VE :** `update` dans la console du conteneur. Il demande d’abord et revient en
  arrière si la nouvelle version ne démarre pas.
- **Home Assistant :** Home Assistant propose la mise à jour. Activez
  **Conserver une sauvegarde de la dernière version** dans sa boîte de dialogue de mise à jour.
- **Unraid :** l’onglet **Docker** propose la mise à jour : **apply update**.

Avec une destination de sauvegarde définie, Kept prend un instantané avant de migrer.
[Mises à niveau et retour en arrière](/fr/admin/upgrades/).
