<InstallPath id="compose">

<Need>
Docker with the Compose plugin, and a terminal. Tested on 1 GB of RAM and one CPU core; Kept and
its database use about 200–400 MB of it ([what was tested](/install/hardware/)).
</Need>

<Steps>

1. **Download `compose.yaml`** into a folder of its own: Kept and its database in one file, with no
   copy of the repository and no passwords to make.

   <Code code={commands.compose.download} lang="sh" />

2. **Write `.env`.** `init` asks for the address you'll open Kept at, such as
   `http://kept.home.arpa:8080`. Use a name rather than an IP address: printed labels carry it.

   <Code code={commands.compose.init} lang="sh" />

   <See>
   <Code code={printed.init} lang="text" />
   </See>

3. **Start it.** The database starts, two one-shot services make its logins and apply the
   migrations, then Kept starts on port 8080.

   <Code code={commands.compose.start} lang="sh" />

   <See>
   At the address, Kept's **Enter the setup code** page.
   </See>

4. **Set up.** Enter the code `init` showed and create the first account: it becomes the instance
   admin.

5. **Keep the keys.** Print the recovery kit and keep it somewhere other than this server, such as
   a password manager. A backup brings back secret values only with these keys.

   <Code code={commands.compose.recoveryKit} lang="sh" />

   <See>
   Text that starts with `KEPT RECOVERY KIT`.
   </See>

</Steps>

## Something not working?

- **The container keeps restarting.** Read its log: `docker compose logs kept`. Kept checks its
  settings before it starts and stops with one line naming the first problem, such as
  `kept: invalid environment: KEPT_PUBLIC_URL` (run `docker compose run --rm init`). If
  `docker compose up -d` stops at `bootstrap`, `docker compose logs bootstrap` says why. On less
  than 1 GB of memory, a backup can run out of it and Docker restarts Kept
  ([what it needs](/install/hardware/)).
  [More](/admin/troubleshooting/#kept-exits-at-start-with-kept-invalid-environment--or-another-kept-line)
- **The port is in use.** Kept takes port 8080 on the host. Run `docker compose run --rm init`
  again with an `http://` address on a free port: it writes the address and the port
  (`KEPT_HTTP_PORT`) to `.env`. Then `docker compose up -d`. In the Home Assistant app, change the
  port under **Configuration → Network** and set **Kept's address** to match.
  [More](/install/compose/#1-write-env)
- **Permission denied.** Kept runs as user 10001 with a read-only filesystem, so a folder you
  mount into it, such as a backup directory, must be owned by uid 10001. `init` writes `.env`
  into the folder you run it from: run it in a folder you own.
  [More](/admin/troubleshooting/#backups-dont-run-or-the-backup-stale-alert-fires)
- **Other devices can't open it.** `localhost` opens on this machine only. Use a name the other
  devices can find, set in your router's DNS or each device's hosts file, and run `init` again
  with it. If Kept says "This Kept is set up for *address*. Open it there.", open it at exactly
  that address, or list the other one in `KEPT_EXTRA_ADDRESSES`
  ([more than one address](/install/home-network/#more-than-one-address)).
  [More](/admin/troubleshooting/#this-kept-is-set-up-for--or-the-request-did-not-come-from-this-site)
- **A 502 from the reverse proxy.** Kept speaks plain HTTP on port 8080: point the proxy at
  `http://`, not `https://`, on that port ([behind a reverse proxy](/install/reverse-proxy/)).
  Kept starts only once `migrate` has finished; if it failed, `docker compose logs migrate` says
  why.
  [More](/admin/troubleshooting/#kept-doesnt-start-after-an-upgrade-and-migrate-exited-with-an-error)

Everything else: [Troubleshooting](/admin/troubleshooting/).

## Go further

- **HTTPS:** the camera, installing the app, push and location need it.
  [Put Kept on HTTPS](/install/https/), or [Kept on a home network](/install/home-network/) for
  what works without it.
- **The assistant:** ask in plain words, with your own AI provider; Kept works without one.
  [AI providers](/users/ai-providers/), and [Connect an AI client (MCP)](/users/mcp-clients/).
- **Backups:** nightly and encrypted, to a directory, S3 or SFTP. [Backups](/admin/backups/).
- **Mail:** password resets, invitations and reminders by mail, with `KEPT_SMTP_URL` and
  `KEPT_SMTP_FROM`. [Mail, push and the calendar feed](/admin/notifications/).
- **Home Assistant:** the integration brings what's due into dashboards and automations.
  [Home Assistant](/users/home-assistant/).

## Updates

- **Docker Compose:** set `KEPT_IMAGE` in `.env` to the new release, then:

  <Code code={commands.compose.update} lang="sh" />

  A release that changes `compose.yaml` says so in its notes: download its file over yours.
- **From source:**

  <Code code={commands.source.update} lang="sh" />

- **Kubernetes:** each release publishes a chart of the same version, and its migrations run in a
  Job before the new version serves.
- **Home Assistant:** Home Assistant offers the update. Turn on **Keep backup of the last
  version** in its update dialog.

With a backup target set, Kept takes a snapshot before it migrates.
[Upgrades and rollback](/admin/upgrades/).
