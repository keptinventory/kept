لا يرسل Kept أي شيء عن نفسه إلى أي مكان ما لم تُعدّه: **لا قياس عن بُعد من أي نوع**، ولا حتى عمليات تثبيت اختيارية.

## فحوصات الصحة

| المسار | ماذا يجيب |
|---|---|
| `/healthz` | ٢٠٠ طالما تخدم العملية HTTP. لفحص البقاء. |
| `/readyz` | ٢٠٠ عندما تجيب اتصالا قاعدة بيانات الويب كلاهما، وإلا ٥٠٣. للاستعداد، و`HEALTHCHECK` الصورة الخاص. |
| `/version` | الإصدار، الالتزام الذي بُني منه، مستودع المصدر، وأين توجد إشعارات الجهات الخارجية (`/notices.txt`، في الصورة). |

حاوية تشغّل العامل فقط (`KEPT_ROLE=worker`) لا تخدم HTTP. `HEALTHCHECK` الصورة يتبع `KEPT_ROLE`: للعامل يتحقق من أن حلقة المهام استطلعت قاعدة البيانات خلال ٢ دقائق الأخيرتين (تلمس `/tmp/kept-worker-alive` أثناء عملها)، لذا لا يحتاج النشر المنفصل إلى تجاوز healthcheck.

## صفحة الحالة والتنبيهات

**الإدارة → الحالة** تُظهر ما يحتاج انتباه: طقم الاسترداد، البريد، مهام الخلفية الفاشلة، فحص التذكير، والنسخ الاحتياطية: عمر النسخة الاحتياطية، آخر تمرين استرداد، إصدار الحاوية، مساحة القرص، الإصدار وتهجيراته، فحص التحديث، HTTPS والموصلات. تصل تنبيهات الإدارة إلى مديري المثيل في التطبيق، بالبريد وبالضغط؛ يُحل كل منها عندما يزول سببه.

## المقاييس

عيّن `KEPT_METRICS_TOKEN` ويخدم `/metrics` نص Prometheus للطلبات التي ترسله كرمز حامل (`Authorization: Bearer <token>`); بدونه، المسار غير موجود. يمرر Compose المتغير من `.env`.

| Metric | What |
|---|---|
| `kept_build_info{version, revision}` | دائمًا ١؛ البناء الجاري |
| `kept_process_uptime_seconds` | ثوانٍ منذ بدء العملية |
| `kept_process_resident_memory_bytes` | ذاكرة العملية |
| `kept_db_pool_connections{pool, state}` | اتصالات لكل مجمع قاعدة بيانات: الإجمالي، الخاملة، المنتظرة |
| `kept_backup_last_success_timestamp_seconds` | متى انتهت آخر نسخة احتياطية جيدة (٠ قبل الأولى) |
| `kept_backup_last_run_status{status}` | ١ لحالة آخر تشغيل منتهي، ٠ للآخرين |
| `kept_disk_used_ratio{volume}` | ما مدى امتلاء قرص البيانات وهدف النسخة الاحتياطية للمجلد |
| `kept_update_available` | ١ عندما يرى فحص التحديث إصدارًا أحدث |

لا تحتفظ أي تسمية بمسار أو هدف أبدًا. قاعدة بيانات لا تجيب تترك أسطر النسخة الاحتياطية، القرص، والتحديث؛ الكشط نفسه لا يزال ينجح.

## السجلات

أسطر JSON على المخرج القياسي (`KEPT_LOG_FORMAT=json`، الافتراضي)، أو `pretty` لقراءة `docker compose logs` بالعين؛ `KEPT_LOG_LEVEL` يضبط المستوى. لكل طلب معرف، يُعاد في رأس الاستجابة `x-request-id`، حتى يمكن مطابقة تقرير بسطر سجله. تُحذف الرموز في عناوين URL من السجل، ولا تُسجّل الأسرار وكلمات المرور أبدًا.

## التتبع وإعداد تقارير الأخطاء

كلاهما اختياري ومعطل افتراضيًا.

- **التتبع:** مع تعيين `OTEL_EXPORTER_OTLP_ENDPOINT`، يرسل Kept آثار OpenTelemetry لطلباته HTTP واستعلامات قاعدات البيانات إلى جامِعك. غير معين، لا يُحمّل أي من كود التتبع حتى، وجامِع معطل لا يبطئ طلبًا أبدًا.
- **إعداد تقارير الأخطاء:** مع DSN متوافق مع Sentry في `KEPT_ERROR_DSN`، تُبلّغ الأخطاء غير المُعالجة مع معرف الطلب والمسار، ولا يُبلّغ أبدًا نص الطلب، رأس، سلسلة استعلام، اسم، أو أي شيء مخزن في موقع.
