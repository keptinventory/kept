يعمل Kept على شبكتك المنزلية على عنوان `http://` عادي، مثل `http://192.0.2.20:8080`
أو `http://kept.home.arpa:8080`. بياناتك الخاصة تعمل هناك: إضافة الأشياء والعثور عليها ونقلها،
والصور والملفات، والوسوم، والتقارير، والاستيراد، والتصدير دون قيم سرية.

بعض الأشياء تحتاج HTTPS. بعضها لأن Kept يرفض تسليم مفتاح أو إظهار سر على
اتصال يمكن لأي شخص على الشبكة قراءته؛ وأخرى لأن المتصفحات تسمح بها فقط على عنوان آمن،
وهو ما لا يستطيع Kept تغييره.

## ما يعمل عبر HTTP العادي

| | عبر HTTP العادي | السبب |
|---|---|---|
| الأشياء، الأماكن، البحث، النقل، الوسوم، التقارير | يعمل | |
| الصور والملفات، المختارة من الجهاز | يعمل | |
| الاستيراد (Homebox، CSV، تصدير Kept) | يعمل | |
| فتح أسرار التصدير عند استيراده | يحتاج HTTPS. عبر HTTP العادي يُستورد باقي التصدير بدونها | Kept: عبارة المرور والقيم السرية |
| تصدير بدون قيم سرية | يعمل. تُستبعد كل قيمة سرية وتُعلَّم بأنها مستبعدة؛ يُستورد التصدير كالمعتاد | بياناتك الخاصة |
| تعيين قيمة سرية | يعمل | |
| إظهار قيمة سرية | يحتاج HTTPS | Kept: السر لا يُرسل أبدًا عبر HTTP العادي |
| تصدير مع قيم سرية | يحتاج HTTPS | Kept: الأسرار وعبارة مرورها |
| رموز تطبيقات الذكاء الاصطناعي (MCP) و Home Assistant | ليس من المتصفح. اصنع واحدًا على الخادم: `kept admin token create` ([CLI](/ar/admin/cli/#رمز-من-الخادم)) | Kept: الرمز مفتاح |
| توصيل تطبيق بـ OAuth (موصل) | يحتاج HTTPS | Kept: OAuth يحتاج عنوانًا آمنًا |
| تنزيل مجموعة الاسترداد | ليس من المتصفح. على الخادم: `kept admin recovery-kit` ([CLI](/ar/admin/cli/)) | Kept: تحتفظ بمفاتيح الخادم |
| إعدادات النسخ الاحتياطي واختبارها | يحتاج HTTPS، أو اضبطها في بيئة الخادم ([التكوين](/ar/reference/configuration/)) | Kept: كلمة مرور النسخ الاحتياطي |
| مفاتيح المرور | تحتاج HTTPS | المتصفح: لا مفاتيح مرور على عنوان HTTP عادي |
| الكاميرا، تثبيت Kept، العمل دون اتصال، إشعارات الدفع، الموقع | تحتاج HTTPS | المتصفح |

عبر HTTP العادي، تسجيل الدخول يستمر ١٢ ساعة ولا يُجدد؛ عبر HTTPS يستمر ٣٠ يومًا. لتغيير الـ ١٢ ساعة، انظر [سأبقى على شبكة منزلي](#البقاء-على-شبكتك).

الشاشة "البدء على الرئيسية" تطلب من مسؤول النسخة وضع Kept على HTTPS. إذا كنت ستبقى على شبكتك المنزلية، اختر **سأبقى على شبكة منزلي** وتعتبر الخطوة مكتملة. سطر HTTPS أعلى كل صفحة يمكن تجاهله أيضًا.

`localhost` يُحسب عنوانًا آمنًا في المتصفحات، لكن Kept يعتمد على `KEPT_PUBLIC_URL`: طالما هو `http:`، تنطبق رفضات Kept أعلاه على `localhost` أيضًا.

## البقاء على شبكتك

من يشغل Kept يمكنه تغيير أمرين على الخادم: مدة بقاء تسجيل الدخول عبر HTTP العادي، والعناوين التي يجيب عليها Kept. لا يمكن تغيير أي منهما من التطبيق، وتعرض Admin → Status ما هو ساري المفعول.

### تسجيل دخول أطول عبر HTTP العادي

عبر HTTP العادي تسجل الدخول مرة أخرى كل ١٢ ساعة. `KEPT_HTTP_SIGN_IN_DAYS` في `.env` يجعلها ذلك العدد من الأيام، ١ إلى ٣٠، تتجدد مع الاستخدام. ٧ تناسب شبكة منزلية أو Tailscale:

```sh
KEPT_HTTP_SIGN_IN_DAYS=7
```

ثم `docker compose up -d`. في تطبيق Home Assistant هو خيار **Sign-in length over http**.

نسخة مطورة من 1.14.4 بتغيير `KEPT_IMAGE` وحدها لا تزال تملك `compose.yaml` القديم،
الذي لا يمرر هذا الإعداد: [نزِّل الجديد](/ar/admin/upgrades/#إعدادات-تحتاج-composeyaml-الجديد)
أولًا.

**التكلفة:** عبر HTTP العادي يمكن لأي شخص يرى حركة المرور نسخ كعكة تسجيل الدخول.
مع تفعيل الإعداد، النسخة المنسوخة تستمر في العمل طالما تُستخدم، حتى يسجل ذلك الجهاز الخروج أو تسجِّل أجهزتك الأخرى الخروج. لذا اقتصر على شبكة تثق بها، وسجِّل الخروج على جهاز تفقده.

| | غير مُضبط | مُضبط |
|---|---|---|
| تسجيل دخول عبر HTTP العادي يستمر | ١٢ ساعة | ذلك العدد من الأيام |
| يتجدد | لا | مرة واحدة في يوم استخدام (عند ١، بعد نصف يوم) |
| عبر HTTPS | ٣٠ يومًا، يتجدد | ٣٠ يومًا، يتجدد: الإعداد لا يفعل شيئًا |
| الأسرار والمفاتيح عبر HTTP العادي | مرفوضة | مرفوضة |
| إجراءات حساسة | كلمة مرور، أو تسجيل دخول في آخر عشر دقائق | نفس الشيء؛ التجديد لا يُحسب تسجيل دخول |
| تسجيل الخروج من كل مكان | ينهي كل تسجيل دخول | ينهي كل تسجيل دخول |

أي قيمة أخرى (٠، ٣١، `7d`) توقِف Kept عند البدء مع رسالة توضح ما يتطلبه. تركه فارغًا مثل عدم وجوده.

عند تفعيله، تسجيل دخول موجود بالفعل يأخذ المدة الأطول في المرة القادمة التي يُستخدم فيها. عند إيقافه، ينتهي في وقته الخاص، حتى المدة التي كان يملكها؛ لإنهائه أسرع، استخدم **تسجيل الخروج من كل مكان** في Admin → Users.

### أكثر من عنوان واحد

Kept يقبل تسجيلات الدخول والحفظ من `KEPT_PUBLIC_URL` فقط، لذا طريقة ثانية للوصول لنفس Kept، اسم Tailscale بجانب اسم LAN، أو IP بجانب اسم، تقول "تم إعداد هذا Kept لـ …". `KEPT_EXTRA_ADDRESSES` يسرد الباقي، مفصولاً بفواصل، تمامًا كما يعرضها المتصفح:

```sh
KEPT_PUBLIC_URL=http://kept.lan:8080
KEPT_EXTRA_ADDRESSES=http://192.0.2.20:8080,http://<machine>.<tailnet>.ts.net:8080
```

ثم `docker compose up -d`. في تطبيق Home Assistant هو خيار **Extra addresses**. يعمل نفس الشيء عبر HTTPS.

نسخة مطورة من 1.14.4 بتغيير `KEPT_IMAGE` وحدها لا تزال تملك `compose.yaml` القديم،
الذي لا يمرر هذا الإعداد: [نزِّل الجديد](/ar/admin/upgrades/#إعدادات-تحتاج-composeyaml-الجديد)
أولًا.

| | `KEPT_PUBLIC_URL` | عنوان إضافي |
|---|---|---|
| استخدام Kept، تسجيل الدخول بكلمة مرور أو رمز لمرة واحدة | نعم | نعم |
| رابط بريد إلكتروني أو إعادة تعيين كلمة مرور | يفتح هنا | يفتح عند `KEPT_PUBLIC_URL` |
| مفاتيح المرور | نعم، عبر HTTPS | لا؛ مفتاح مرور ينتمي لعنوان واحد |
| تسجيل دخول Google و OIDC | نعم | الزر يفتح `KEPT_PUBLIC_URL` |
| تطبيقات الذكاء الاصطناعي (MCP، OAuth) | نعم | صلها عند `KEPT_PUBLIC_URL`: `/mcp` يرفض هذا العنوان، وموافقة OAuth تُرفض هنا |
| روابط، وسوم، رموز QR، بريد، موجزات تقويم | تشير إلى هنا | لا تزال تشير إلى `KEPT_PUBLIC_URL` |

- **كل عنوان يسجل الدخول بشكل منفصل ويثبت كتطبيق خاص به،** لأن المتصفحات تحتفظ بالكعكات
  والبيانات غير المتصلة لكل عنوان. تسجيل الخروج على واحد يترك الآخر مسجلاً الدخول؛ **تسجيل الخروج من كل مكان**
  ينهي كلاهما. إشعارات الدفع، حيث يسمح بها HTTPS، تفتح على العنوان الذي فعَّلها الجهاز عنده. منفذان على اسم مضيف واحد يشتركان في كعكاتهما: المتصفحات لا تحتفظ بتلك لكل منفذ.
- **رابط بريد إلكتروني** طُلب على عنوان إضافي يفتح عند `KEPT_PUBLIC_URL` ويسجِّلك الدخول هناك،
  لا حيث طلبت. إعادة تعيين كلمة المرور تضبط كلمة المرور هناك؛ ثم سجِّل الدخول على العنوان الذي كنت عليه. إذا تعذر الوصول لـ `KEPT_PUBLIC_URL` من حيث أنت، استخدم كلمة مرورك.
- **مفاتيح المرور:** أضفها واستخدمها عند `KEPT_PUBLIC_URL`. عنوان إضافي يعرض كلمة مرورك أو
  رابط بريد إلكتروني ويوضح السبب.
- **عناوين دقيقة:** مخطط، مضيف ومنفذ، تُقارن كاملة. `http://kept.lan` ليس
  `http://kept.lan:8080`، و `kept.lan.example.com` ليس `kept.lan`. حرف بدل، مسار، تسجيل دخول أو
  مزيج من `http` و `https` يوقف Kept عند البدء مع رسالة تحدد أيهم. تركه فارغًا مثل عدم وجوده.
- **رؤوس موجهة:** `Host` و `X-Forwarded-*` لا دور لها، لذا لا يستطيع الوكيل إضافة عنوان
  بالخطأ، أو إزالة واحد. وجِّهه إلى Kept لكل عنوان تسرده.

**التكلفة:** صفحة مُخدمة عند عنوان مسرد تُحسب Kept نفسه، ويمكن أن تستخدم تسجيل دخول
من يفتحها هناك. لذا سرد فقط العناوين التي تصل لهذا Kept، على أسماء وعناوين IP تتحكم بها.

## أضف HTTPS: Tailscale أولاً

أقل عمل لأسرة: ثبِّت Tailscale على الجهاز الذي يشغل Kept وعلى كل هاتف وحاسوب يستخدمه، فعِّل شهادات HTTPS لشبكتك الخلفية، وشغِّل Kept مع

```sh
tailscale serve --bg 8080
```

يكون Kept عندها عند `https://<machine>.<tailnet>.ts.net`، مع شهادة يثق بها كل جهاز مسبقًا،
من المنزل أو بعيدًا. اضبط `KEPT_PUBLIC_URL` على ذلك العنوان وأعد تشغيل Kept. المزيد في
[ضع Kept على HTTPS](/ar/install/https/#tailscale).

## أضف HTTPS: Caddy مع سلطة شهادات خاصة به

بدون Tailscale ودون نطاق عام، يمكن لـ Caddy توقيع شهادة لاسم شبكة منزلية بنفسه (`tls internal`). يعمل، لكنه ليس سريعًا: **يجب إخبار كل جهاز يفتح Kept بالثقة في شهادة جذر Caddy**، واحد تلو الآخر، لكل شخص في المنزل. حتى يثق جهاز به، متصفحه يعرض تحذير أمان.

١. اختر اسمًا يستطيع كل جهاز تحليله للجهاز، مثلًا `kept.home.arpa` (إدخال DNS على راوترك، أو إدخال في ملف hosts لكل جهاز).
٢. اضبطه في `.env`:

   ```sh
   KEPT_DOMAIN=kept.home.arpa
   KEPT_PUBLIC_URL=https://kept.home.arpa
   ```

٣. يأتي Caddy مع `compose.full.yaml`: نزِّله و `docker/caddy/Caddyfile`، واضبط
   `COMPOSE_FILE=compose.full.yaml` في `.env`، كما في
   [ضع Kept على HTTPS](/ar/install/https/#ملف-تعريف-caddy-في-compose). ثم أضف `tls internal` إلى Caddyfile:

   ```caddy
   {$KEPT_DOMAIN} {
   	tls internal
   	encode zstd gzip
   	reverse_proxy kept:8080
   }
   ```

٤. شغِّل Caddy وانسخ شهادته الجذرية من حجم بياناته:

   ```sh
   docker compose --profile https up -d
   docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./kept-root.crt
   ```

٥. ثبِّت `kept-root.crt` على كل جهاز وائتمنه:
   - **iPhone و iPad:** أرسله للجهاز (AirDrop أو بريد)، ثبِّت الملف الشخصي في
     الإعدادات → عام → VPN وإدارة الجهاز، ثم فعِّل الثقة الكاملة له في الإعدادات →
     عام → حول → إعدادات ثقة الشهادات.
   - **Android:** في إعدادات الأمان، ثبِّته كشهادة CA (اسم القائمة يختلف حسب الصانع). بعض التطبيقات تتجاهل الشهادات المثبتة من المستخدم.
   - **أجهزة كمبيوتر:** أضفه إلى شهادات النظام الموثوقة (Keychain Access على Mac، مدير الشهادات على Windows، مستودع CA للتوزيعة على Linux). Firefox قد يحتفظ بقائمته الخاصة.

جذر Caddy يدوم عشر سنوات؛ الشهادات التي يوقعها به تتجدد ذاتيًا. مفتاح الجذر الخاص يبقى في حجم `caddy-data`: من ينسخه يستطيع التوقيع لأي اسم أجهزتك تثق به الآن، فاحرس ذلك الحجم مثل كلمة مرور. [mkcert](/ar/install/https/#شهادة-تثق-بها-أجهزتك-فقط) نفس الفكرة بأداة أخرى.

## فتح Kept على العنوان الصحيح

افتح Kept على العنوان في `KEPT_PUBLIC_URL`. إذا فُتح على آخر (عنوان IP للجهاز بينما URL يسمي `kept.home.arpa` مثلًا)، تسجيل الدخول يقول أي عنوان تم إعداد هذا Kept له، مع رابط إليه.
