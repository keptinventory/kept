Kept працює як додаток Home Assistant: Kept і власна база даних в одному додатку, на Home Assistant OS. Жодного Docker Compose, жодних паролів, які треба створювати, і резервні копії Home Assistant охоплюють його.

## Додаток Home Assistant чи звичайне встановлення?

Той самий Kept, та сама версія, ті самі можливості: речі, місця, мапа й граф, сканування, мітки, ШІ, MCP, імпорти, Paperless, кілька людей.

| | Додаток Home Assistant | [Compose](/uk/install/compose/) або [Kubernetes](/uk/install/kubernetes/) |
|---|---|---|
| Відкривається | Бічна панель Home Assistant і власна адреса Kept (порт 8080) | Власна адреса Kept |
| Встановлення, оновлення | Крамниця додатків Home Assistant | `docker compose`, `helm` |
| Перший обліковий запис | Адміністратор Home Assistant налаштовує без коду | Код налаштування з журналу Kept |
| Налаштування | Вкладка **Configuration** додатка | `.env` або значення чарту |
| Офлайн, встановлення застосунку телефону, push | Власна адреса Kept через https; не в бічній панелі | Через https |
| Ключі доступу, OIDC, Google | Власна адреса Kept (https для ключів доступу; https і публічне доменне ім'я для Google) | Адреса Kept |
| Резервні копії | Резервні копії Home Assistant; поза пристроєм через його [розташування резервних копій](https://www.home-assistant.io/common-tasks/general/backups/) | Власні щоденні резервні копії Kept: restic до теки, S3 або SFTP |
| Фото й файли | У даних додатка | На диску або в S3 |

- **Додаток:** ви вже запускаєте Home Assistant OS.
- **Compose або Kubernetes:** усе інше; або фото й файли в S3; або власні резервні копії Kept
  поза пристроєм.

## Встановлення

<HomeAssistantButton />

1. **Налаштування → Додатки → Встановити додаток → ⋮ → Репозиторії**, додайте
   `https://github.com/keptinventory/kept` (або скористайтеся кнопкою вище).
2. Знайдіть **Kept**, потім **Почати**.
3. **Відкрити веб-інтерфейс**. Kept відкривається всередині Home Assistant, також у бічній панелі.

| Потрібно | |
|---|---|
| Home Assistant OS | Додаткам потрібен Supervisor: не Home Assistant Container або Core. Supervisor 2026.10.4 або пізніше |
| `aarch64` або `amd64` | Raspberry Pi 4 або 5 на 64-бітній системі, міні-ПК, віртуальна машина |
| 4 ГБ пам'яті | 2 ГБ працює з небагатьма іншими додатками; Kept з базою даних використовує приблизно 250–320 МБ у простій |

## Перший запуск

- Адміністратор Home Assistant, який відкриває Kept з Home Assistant, налаштовує його без коду
  (Supervisor 2026.10.4 або пізніше; до того код потрібен).
- Усі інші вводять код налаштування з вкладки **Журнал** додатка (`KEPT SETUP CODE: XXX-XXX`).
- У Kept власні облікові записи. Люди входять у Kept один раз, також усередині Home Assistant; членам домогосподарства не потрібно бути адміністраторами Home Assistant, щоб використовувати його з бічної панелі.

## Власна адреса Kept

Усередині Home Assistant Kept відкривається з бічної панелі. Телефонам, надрукованим QR-міткам, посиланням у пошті, інтеграції та застосункам ШІ потрібна адреса, що працює поза сеансом Home Assistant, тому додаток також надає Kept на **порті 8080**. Вкладка **Журнал** називає її, наприклад `Kept is at http://homeassistant.local:8080`.

| Параметр | Що |
|---|---|
| Власна адреса Kept | Вкажіть її, коли `homeassistant.local` не розв'язується у вашій мережі або змінився порт. `http(s)://host[:port]`, без шляху. |
| https на порті Kept | Надає порт через https із сертифікатом Home Assistant з `/ssl` (від додатків DuckDNS або Let's Encrypt). Перезапустіть додаток після оновлення сертифіката. |
| HSTS | `on` за замовчуванням. `off`, коли сам Home Assistant або інший додаток з цим іменем хоста працює через звичайний http: HSTS Kept охоплює ім'я хоста на кожному порті, зокрема 8123 ([HSTS](/uk/install/reverse-proxy/#hsts)). |
| Тривалість входу через http | Порожньо: 12 годин, не продовжується. Дні, які триває вхід через звичайний http, від 1 до 30, продовжується під час використання. Не впливає, коли https увімкнено; витрати описано в [Залишаючись у своїй мережі](/uk/install/home-network/#залишаюся-у-вашій-мережі). |
| Додаткові адреси | Інші адреси, на які відповідає цей Kept, через кому, наприклад `http://192.0.2.20:8080`. Порожньо: одна. Додаються до власної адреси Home Assistant, ніколи не замінюють її ([більше ніж одна адреса](/uk/install/home-network/#більше-ніж-одна-адреса)). |
| Вихідна пошта | URL `smtps://`: посилання для входу, запрошення та нагадування поштою. |
| OIDC, Google | Вхід зі своїм постачальником ідентичності або з Google. Порожньо: вимкнено. |
| Сервер Apprise | Сервер Apprise API для каналів сповіщень Apprise. Порожньо: немає. |
| Реєстрація | `true` або `false` фіксує її відкритою або закритою; якщо не вказано, вирішує адміністратор. |
| Обмеження вивантаження (МБ) | від 1 до 2048; за замовчуванням 25. |

Постачальник повертає людей на власну адресу Kept, ніколи не на Home Assistant. URL перенаправлення для реєстрації: `<Kept's address>/api/v1/auth/callback/oidc` для OIDC, `<Kept's address>/api/v1/auth/callback/google` для Google. Вкладка **Журнал** виводить його, коли вхід налаштовано. Усередині Home Assistant **Увійти через …** відкриває власну адресу Kept у новій вкладці.

Google відхиляє URL перенаправлення через http, з іменем `.local` або з IP-адресою ([правила Google](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation)): встановіть для **Власної адреси Kept** https із публічним доменним іменем, наприклад ім'я DuckDNS з **https на порті Kept**. Вкладка **Журнал** попереджає, якщо це не спрацює.

Вимкнення порту 8080 (Конфігурація → Мережа) залишає лише бічну панель: мітки й застосунок телефону тоді не відкриваються.

## Що потребує https

| | Звичайний http | https |
|---|---|---|
| Речі, місця, пошук, мітки, фото з файлу | так | так |
| Інтеграція Kept, налаштована із застосунку | так | так |
| Особисті токени (скрипти), показ секретів, експорти | ні | так |
| Ключі доступу, камера, встановлення застосунку телефону, push | ні | так |

Усередині Home Assistant Kept вважається https лише тоді, коли сам Home Assistant обслуговується через https. Проксі перед Home Assistant, що завершує TLS, має надсилати `X-Forwarded-Proto: https`, інакше Kept бачить звичайний http. Ключі доступу належать до власної адреси Kept: увійдіть з одним із них там. Більше в [домашній мережі](/uk/install/home-network/).

## Резервні копії та оновлення

- **Резервні копії:** резервні копії Home Assistant включають Kept: базу даних як дамп, фото, файли та ключі Kept. Залишайте шифрування резервних копій Home Assistant увімкненим. Відновлення резервної копії повертає Kept; перший запуск після відновлення триває трохи довше.
- **Резервна копія, коли Kept зупинено,** містить дамп, який Kept записав під час останнього чистого зупинення: Home Assistant просить свіжий дамп лише в запущеного додатка. Після збою запустіть Kept перед резервним копіюванням.
- **Власні резервні копії Kept** немає в додатку: їм потрібен логін власника бази даних, який додаток отримує з запущеного сервера. Адміністрування → Резервні копії каже про це й посилається на резервні копії Home Assistant.
- **Поза пристроєм:** додайте мережеву спільну теку або хмарне розташування в налаштуваннях резервного копіювання Home Assistant ([резервні копії Home Assistant](https://www.home-assistant.io/common-tasks/general/backups/)).
- **Оновлення:** версія додатка — це версія Kept. Оновлення зберігає дані Kept і оновлює його базу даних при запуску. Увімкніть **Keep backup of the last version** у діалоговому вікні оновлення Home Assistant: власний знімок Kept перед оновленням у додатку вимкнено.

## Інтеграція

Цей додаток запускає Kept; окрема інтеграція приводить його в Home Assistant ([додаток і інтеграція](/uk/users/home-assistant/#застосунок-і-інтеграція)).

Встановіть [інтеграцію Kept](/uk/users/home-assistant/) через HACS і перезапустіть Home Assistant: Kept з’явиться як виявлений у **Налаштування → Пристрої та сервіси**. Додайте його, потім дозвольте в Kept (**Налаштування → З’єднання**). Без токена для копіювання і без https: Kept і Home Assistant спілкуються внутрішньою мережею Home Assistant.
