تعمل ميزات Kept الذكية (ملء الأشياء من الصور والإيصالات، المساعد، البحث الدلالي) مع أي مزود يربطه مالك المكان في **الإعدادات → ذكاء اصطناعي**. يشغّل Ollama النموذج على عتادك الخاص، فلا شيء يغادره؛ ويتكلم Kept معه كمزود **متوافق مع OpenAI**.

:::caution[غير مختبر]
لم يُقس Ollama مع Kept. يشارك النموذج ذاكرة الجهاز مع Kept، فخطط لأكثر من [١ غيغابايت خُبر Kept عليها](/ar/install/hardware/)، وتوقّع أن يكون النموذج الصغير أبطأ وأقل دقة من نموذج مستضاف في قراءة الإيصالات.
:::

## إعداده

١. يأتي Ollama مع `compose.full.yaml` لا `compose.yaml`: حمّله واجعل `COMPOSE_FILE=compose.full.yaml` في `.env` ([Caddy و Ollama](/ar/install/compose/#caddy-وollama)). شغّل Kept مع ملف تعريف `ollama`، ثم اسحب نموذجًا إليه بأمر Ollama الخاص:

   ```sh
   docker compose --profile ollama up -d
   docker compose exec ollama ollama pull <model>
   ```

   تسكن النماذج في حجم `ollama`. لا يُنشر شيء على المضيف: فقط Kept، على شبكة Compose، يصل إلى Ollama. حجم الصورة نحو ٣.٨ غيغابايت (amd64) أو ٢.٨ غيغابايت (arm64) قبل أي نموذج.

٢. **السماح بالعناوين الخاصة.** `http://ollama:11434` على شبكة Compose الخاصة، عنوان خاص، و Kept يرفض تلك افتراضيًا ([الطلبات الصادرة](/ar/admin/security-model/#طلبات-صادرة-ssrf)). يشغّل مدير المثيل **الإدارة → الإعدادات → السماح بالعناوين الخاصة** أولًا؛ بدونه، تقول إضافة المزود "ذلك العنوان على شبكة خاصة". ينطبق الشيء نفسه على Ollama (أو LM Studio) في مكان آخر على شبكتك المنزلية.

٣. في **الإعدادات → ذكاء اصطناعي**، أضف مزودًا **متوافقًا مع OpenAI** بعنوان الأساس `http://ollama:11434/v1` والنموذج الذي سحبته. يتجاهل Ollama مفتاح API، فأي قيمة تكفي.
