‏Docker Compose هو طريقة تشغيل Kept على جهاز واحد: Kept نفسه، وPostgres 18 مع pgvector، وإن شئت
Caddy من أجل HTTPS. تحتاج إلى Docker مع إضافة Compose، وإلى جهاز بذاكرة ٢ غيغابايت على الأقل
ونواتَي معالجة ([ما يحتاجه](/ar/install/hardware/)).

أربع خطوات، بلا نسخة من المستودع وبلا كلمات مرور تصنعها بنفسك:

```sh
mkdir kept && cd kept
curl -fsSLO https://raw.githubusercontent.com/keptinventory/kept/v1.14.1/compose.yaml
docker compose run --rm init
docker compose up -d
```

يعمل `compose.yaml` وحده، فيمكن لصقه أيضًا في Portainer وDockge وأمثالهما (راجع
[من دون طرفية](#من-دون-طرفية)).

:::note[الصور]
تُنشر الإصدارات على `ghcr.io/keptinventory/kept` بالوسوم `1` و`1.2` و`1.2.3`، ولا يوجد `latest`
أبدًا، والإصدار `1.0.0` أول إصدار موقَّع. والصور نفسها، موقَّعة بالمفتاح نفسه، موجودة على Docker Hub باسم
`keptinventory/kept`. يشغّل `compose.yaml` الإصدار الذي نُشر معه ما لم يحدد `KEPT_IMAGE` في `.env`
غيره، ويكتب `init` هناك الإصدار الذي عمل به. ويمكنك [التحقق منه](/ar/admin/verify-release/) أولًا.
ولتشغيل صورة تبنيها بنفسك، في نسخة من المستودع: `docker build -t kept:local .` ثم `KEPT_IMAGE=kept:local`.
:::

## ١. اكتب ملف ‎`.env`‎

```sh
docker compose run --rm init
```

يسألك `init` عن **العنوان الذي ستفتح Kept عليه**، مثل `http://kept.home.arpa:8080` أو
`https://kept.example.org`. منه تُبنى الروابط ورموز QR على الملصقات المطبوعة والتحقق من المصدر،
فيجب أن يطابق تمامًا ما يظهر في المتصفح وألا يتغير: **استخدم اسمًا لا عنوان IP.** فقد يعطي جهاز
التوجيه في المنزل هذا الجهاز عنوانًا جديدًا يومًا ما، فتشير الملصقات التي طبعتها إلى لا شيء. اضبط
الاسم في DNS جهاز التوجيه، أو في ملف hosts على كل جهاز. ويبقى عنوان IP ممكنًا إن أكّدته.

ثم يكتب `.env` بجانب `compose.yaml` وفيه ذلك العنوان (`KEPT_PUBLIC_URL`) والمنفذ (`KEPT_HTTP_PORT`،
من عنوان يبدأ بـ`http://`) والصورة ورمز إعداد (`KEPT_SETUP_CODE`)، ويعرض الرمز. لا يحوي `.env`
أي كلمة مرور، ولا يقرؤه غيرك. شغّل `init` مرة أخرى لتغيير العنوان: يحدّث تلك الأسطر ويُبقي كل ما
أضفته. ومن دون طرفية، أعطه العنوان في الأمر: `docker compose run --rm init --url http://kept.home.arpa:8080`.

كل ما عدا ذلك اختياري؛ تشرح التعليقات في `compose.env.example` و[مرجع الإعدادات](/ar/reference/configuration/)
عمل كل متغير.

## ٢. شغّله

```sh
docker compose up -d
```

يبدأ Compose قاعدة البيانات وينتظر جاهزيتها، ثم:

- **‏`bootstrap`** (لمرة واحدة، `kept bootstrap`) ينشئ حسابات الدخول الأربعة لقاعدة البيانات
  والإضافات `pg_trgm` و`unaccent` و`vector`. في أول تشغيل يولّد كلمة مرور كل حساب في وحدة تخزين،
  وفي كل تشغيل يضبط كلمة مرور كل حساب على تلك القيمة، فيتفق Postgres وKept دائمًا.
- **‏`migrate`** (لمرة واحدة، `kept migrate`) يطبّق تحديثات مخطط قاعدة البيانات مرة واحدة تحت قفل.
- **‏Kept** يبدأ على المنفذ 8080 (يغيّر `KEPT_HTTP_PORT` منفذ الجهاز).

## ٣. أكمل الإعداد

افتح العنوان وأدخل رمز الإعداد الذي عرضه `init` وأنشئ الحساب الأول: يصبح مدير النسخة. ويطبع Kept
الرمز أيضًا في سجله عند أول تشغيل:

```sh
docker compose logs kept | grep "KEPT SETUP CODE"
```

ويُصدَر الرمز المفقود من جديد بالأمر:

```sh
docker compose run --rm migrate admin setup-code
```

الرموز الخاطئة تقفل الإعداد مدةً، لكل عنوان وللنسخة كلها. وإن كان Kept خلف وكيل لا يثق به، يتشارك
الجميع عنوان الوكيل؛ راجع [الوكلاء العكسيين](/ar/install/reverse-proxy/).

## ٤. احفظ المفاتيح

في أول تشغيل، ومع ترك `KEPT_SECRET_KEY` و`KEPT_AUTH_SECRET` فارغين، يولّدهما Kept في مجلد
`kept-config` ويكتب سطرًا واحدًا في السجل يقول أين. المفتاح السري يختم كل قيمة سرية (مفاتيح الذكاء
الاصطناعي وكلمات المرور التي تحفظها في Kept): **النسخة الاحتياطية تستعيد كل شيء ما عدا هذه القيم إن
لم يكن المفتاح معك.**

اطبع المفاتيح واحفظها في مكان غير هذا الخادم، كمدير كلمات مرور:

```sh
docker compose exec kept kept admin recovery-kit
```

تطلب صفحة الإدارة ← الحالة إقرارك بحزمة الاسترداد، ويشترطه Kept قبل أول قيمة سرية أو مفتاح ذكاء
اصطناعي أو إعداد نسخ احتياطي. راجع [حزمة الاسترداد](/ar/admin/recovery-kit/).

## ٥. بعد ذلك

- [شغّل Kept عبر HTTPS](/ar/install/https/): الكاميرا وتثبيت التطبيق والإشعارات والموقع لا تعمل
  إلا عبر HTTPS.
- [أعدّ النسخ الاحتياطي](/ar/admin/backups/).
- البريد: اضبط `KEPT_SMTP_URL` (‏`smtp://` أو `smtps://` مع بيانات الدخول) و`KEPT_SMTP_FROM` من
  أجل استعادة كلمات المرور والدعوات والتذكيرات بالبريد. وبدونهما تصل التذكيرات داخل التطبيق فقط،
  وتقول صفحة الإدارة ← الحالة إن البريد غير مُعَدّ.

## ما ينشئه Compose

| المجلد | ما فيه | انسخه احتياطيًا؟ |
|---|---|---|
| `kept-db` | قاعدة بيانات Postgres | عبر النسخ الاحتياطي في Kept، ولا تنسخ المجلد أثناء التشغيل أبدًا |
| `kept-data` | الملفات المرفوعة (مع `KEPT_STORAGE=local`، الافتراضي) | عبر النسخ الاحتياطي في Kept |
| `kept-config` | ‏`KEPT_SECRET_KEY` و`KEPT_AUTH_SECRET` المولَّدان، وكلمات مرور الحسابات `kept_app` و`kept_auth` و`kept_system` | احفظ حزمة الاسترداد؛ وتُولَّد كلمات المرور من جديد إن ضاعت |
| `kept-owner` | كلمة مرور الحساب `kept_owner` | لا؛ تُولَّد من جديد إن ضاعت |
| `caddy-data` و`caddy-config` | شهادات Caddy (ملف التعريف `https`) | لا؛ يحصل Caddy على شهادات جديدة |

ليس للمستخدم الأعلى في قاعدة البيانات كلمة مرور يحتاجها أحد: لا يُوصَل إليه إلا من داخل حاوية
قاعدة البيانات، بالأمر `docker compose exec db psql -U postgres`، ومن `bootstrap` الذي يشارك تلك
الحاوية شبكتها. وعبر الشبكة يحتاج كل حساب إلى كلمة مروره. لا تنشر منفذ خدمة `db` أبدًا (لا
`ports:` عليها): يصل إليها Kept عبر شبكة compose.

تعمل حاويات Kept بمستخدم غير جذري (uid 10001)، بنظام ملفات جذري للقراءة فقط، مع إسقاط كل صلاحيات
لينكس و`no-new-privileges`. تحمل خدمة `migrate` حساب مالك قاعدة البيانات، ولا تراه الحاوية التي
تخدم الطلبات (لا تُركَّب فيها `kept-owner`) إلا إذا أعطيتها إياه للنسخ الاحتياطي الليلي
([النسخ الاحتياطي](/ar/admin/backups/)). و`init` هو الاستثناء الوحيد: يعمل بصلاحية الجذر، بلا شبكة،
ومعه فقط الصلاحيتان اللتان تنشئان `.env` في مجلدك وتعطيانك ملكيته، ثم يخرج.

## من دون طرفية

يقبل Portainer وDockge وأمثالهما `compose.yaml` كما هو. ولا يشغّلون `init`، فاضبط بدلًا منه متغيرين
في محرّر البيئة لديهم: `KEPT_PUBLIC_URL` (العنوان، كما سبق) و`KEPT_SETUP_CODE` (ستة محارف من 0–9 وA–Z
بلا I وL وO وU، مثل `KPT-2X9`؛ أو اتركه فارغًا واقرأ الرمز من سجل Kept). وثبّت `KEPT_IMAGE` على
إصدار إن لم تفعل الأداة ذلك.

## تثبيت أقدم من 1.13.0

التثبيت المصنوع بنسخة من المستودع فيه أسطر `KEPT_DB_*_PASSWORD` الخمسة في `.env`. ومع `compose.yaml`
هذا تُستخدم كما هي ولا يُولَّد شيء: حدّث نسختك (أو نزّل `compose.yaml` الجديد بجانب `.env` القديم)
ثم شغّل `docker compose up -d`. وحذف تلك الأسطر لاحقًا، أو كتابة `.env` من جديد بالأمر `init`، آمن
أيضًا: يولّد التشغيل التالي كلمات مرور جديدة ويضبطها في Postgres. وكان `KEPT_IMAGE` الفارغ يبني
الصورة من النسخة؛ أما الآن فيشغّل الإصدار الذي يحدده `compose.yaml`، فاضبط `KEPT_IMAGE=kept:local` إن
كنت تبني صورتك بنفسك.
