**Спочатку заберіть свої дані.** Після зникнення томів їх не повернути, хіба що резервна копія.

1. Кожен власник експортує свої локації (**Налаштування → Експорт**), або зберігає найновішу резервну копію та [набір для відновлення](/uk/admin/recovery-kit/) у безпечному місці: самим restic пізніше все ще можна [прочитати інвентар](/uk/admin/read-with-restic/).
2. Зупиніть і видаліть контейнери **та їхні томи** у теці з `.env`:

   ```sh
   docker compose --profile https --profile ollama down --volumes
   ```

   Це видаляє `kept-db` (базу даних), `kept-data` (файли), `kept-config` (згенеровані ключі та паролі бази даних) і `kept-owner` (пароль входу власника); із `compose.full.yaml` — також сертифікати Caddy та моделі Ollama. Без `--volumes` дані залишаються на машині.
3. Видаліть образ: `docker image rm ghcr.io/keptinventory/kept:<version>` (теґ, який ви запускали, або `kept:local` для власної збірки), а також `.env` поруч із Compose-файлом.
4. Поза машиною видаліть те, що ви самі налаштували для Kept:
   - **файловий бакет** із `KEPT_STORAGE=s3` (та його старі версії, якщо було увімкнене версіонування);
   - **резервна копія**: тека `restic` на диску резервного копіювання, префікс `restic/` у бакеті резервного копіювання або сховище на SFTP-сервері, а також будь-які alpha `runs/` і `blobs/` поруч із нею;
   - базу даних, якщо вона була провайдера: ролі `kept_*` та саму базу даних;
   - DNS-записи, маршрути проксі та `serve` Tailscale, яке ви додали.
