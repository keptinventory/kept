Kept працює в Unraid як один контейнер із **Community Applications** (вкладка **Apps**): Kept і
власна база даних PostgreSQL, усе в `/mnt/user/appdata/kept`. Без Compose, без паролів, які треба
вигадувати.

## Що потрібно

| | |
|---|---|
| Unraid | Із вкладкою **Apps** (плагін Community Applications) |
| Пам’ять | Близько 500 МБ вільних для Kept і його бази даних, 1 ГБ для імпорту й резервних копій |
| Адреса | Та, за якою ви відкриватимете Kept, наприклад `http://tower.local:8080`. Беріть ім’я, а не IP-адресу: її несуть надруковані етикетки |

## Встановлення

1. **Apps**, знайдіть **Kept**, потім **Install**.
2. **Kept's address**: адреса, за якою ви відкриватимете Kept, без шляху. Решту можна лишити як
   є. **Show more settings** містить необов’язкові: пошту, вхід через OIDC і Google, зворотний
   проксі, реєстрацію.
3. **Apply.** Unraid завантажує образ і запускає контейнер.
4. Вкладка **Docker**, значок Kept, **Logs**: код налаштування.

   ```text
   app: Kept is at http://tower.local:8080
   KEPT SETUP CODE: XXX-XXX
   ```

5. Значок Kept, **WebUI**. Kept показує **Введіть код налаштування**: введіть код, потім
   **Створіть перший обліковий запис**. Він стає адміністратором екземпляра.
6. **Збережіть ключі.** Значок Kept, **Console**, потім:

   ```sh
   kept admin recovery-kit
   ```

   Скопіюйте текст, що починається з `KEPT RECOVERY KIT`, кудись поза цим сервером, наприклад у
   менеджер паролів. Без ключів резервна копія не поверне секретні значення.

Перший запуск створює базу даних і триває близько хвилини. Docker позначає контейнер здоровим, щойно
Kept відповідає.

## Що лежить у теці appdata

| Тека | Що |
|---|---|
| `postgres/` | Робоча база даних. Належить користувачу `postgres` контейнера |
| `kept/` | Фото й файли. Належать uid 10001, користувачу, від якого працює Kept |
| `config/` | Ключі Kept (`secrets.json`) і паролі бази даних. Належать uid 10001 |
| `owner/` | Пароль власника бази даних. Лише для root: процес Kept ніколи його не читає |
| `backup/kept.pgdump` | Дамп бази даних, що пишеться під час кожної зупинки контейнера |

Контейнер стартує як root, віддає ці теки їхнім власникам, а тоді запускає Postgres і Kept від їхніх
власних користувачів. Сама тека лишається за root: ніхто інший не може переглянути її вміст.

## Резервні копії

- **Робіть резервну копію теки appdata** при зупиненому контейнері, наприклад плагіном Appdata
  Backup для Unraid. Зупинка спершу пише `backup/kept.pgdump`, тож копія містить узгоджену копію
  бази даних, навіть якщо робочі файли такими не є.
- **Відновлення:** поверніть теку на місце й запустіть Kept. Якщо теки `postgres/` немає, а в
  `backup/` є дамп, Kept відновлює базу даних із дампа під час запуску; журнал каже
  `database restored from the backup`.
- **Власні нічні резервні копії Kept** (Адміністрування → Резервні копії) у цьому контейнері не
  налаштовані: їм потрібен логін власника бази даних, якого запущений Kept не має. Робіть копію
  теки appdata.

## Оновлення

Шаблон іде за мажорною версією Kept (`kept-unraid:1`). Коли виходить реліз, вкладка **Docker** показує
оновлення для Kept: **apply update**. Контейнер зупиняється (і пише свій дамп), стартує новий образ,
і Kept оновлює свою базу даних під час запуску.

## Адреса Kept

Змініть її в шаблоні (значок Kept, **Edit**) і **Apply**. Щоб Kept працював через https, поставте
зворотний проксі перед портом 8080, задайте в **Kept's address** його https-адресу, а в
**Trusted reverse proxies** адресу проксі, як її бачить Kept
([за зворотним проксі](/uk/install/reverse-proxy/)). Камера, встановлення застосунку на телефон,
push-сповіщення й ключі доступу потребують https
([Kept у домашній мережі](/uk/install/home-network/)).

## Видалення

1. Вкладка **Docker**, значок Kept, **Remove**. Тека appdata лишається.
2. Щоб видалити й дані, видаліть `/mnt/user/appdata/kept` у терміналі чи файловому менеджері. Це
   не можна скасувати: спершу зробіть резервну копію, якщо дані можуть знадобитися.
