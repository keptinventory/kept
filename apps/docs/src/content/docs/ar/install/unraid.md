يعمل Kept على Unraid كحاوية واحدة من **Community Applications** (تبويب **Apps**): فيها Kept وقاعدة
بيانات PostgreSQL الخاصة به، وكل شيء في `/mnt/user/appdata/kept`. لا Compose، ولا كلمات مرور
تخترعها.

## ما تحتاجه

| | |
|---|---|
| ‏Unraid | مع تبويب **Apps** (إضافة Community Applications) |
| الذاكرة | نحو ٥٠٠ ميغابايت حرة لـ Kept وقاعدة بياناته، و١ جيجابايت للاستيراد والنسخ الاحتياطي |
| عنوان | العنوان الذي ستفتح عليه Kept، مثل `http://tower.local:8080`. استعمل اسمًا لا عنوان IP: فالملصقات المطبوعة تحمله |

## التثبيت

1. **Apps**، ابحث عن **Kept**، ثم **Install**.
2. **Kept's address**: العنوان الذي ستفتح عليه Kept، بلا مسار. يمكن أن يبقى الباقي كما هو. وفي
   **Show more settings** الإعدادات الاختيارية: البريد، وتسجيل الدخول عبر OIDC وGoogle، والوكيل
   العكسي، والتسجيل.
3. **Apply.** يسحب Unraid الصورة ويشغّل الحاوية.
4. تبويب **Docker**، أيقونة Kept، ثم **Logs**: رمز الإعداد.

   ```text
   app: Kept is at http://tower.local:8080
   KEPT SETUP CODE: XXX-XXX
   ```

5. أيقونة Kept، ثم **WebUI**. يعرض Kept صفحة **أدخل رمز الإعداد**: اكتب الرمز، ثم
   **أنشئ الحساب الأول**. يصبح صاحبه مسؤول النسخة.
6. **احفظ المفاتيح.** أيقونة Kept، ثم **Console**، ثم:

   ```sh
   kept admin recovery-kit
   ```

   انسخ النص الذي يبدأ بـ `KEPT RECOVERY KIT` إلى مكان غير هذا الخادم، مثل مدير كلمات المرور.
   فبلا المفاتيح لا تعيد النسخة الاحتياطية القيم السرية.

يُنشئ التشغيل الأول قاعدة البيانات ويستغرق نحو دقيقة. ويعدّ Docker الحاوية سليمة حين يجيب Kept.

## ما في مجلد appdata

| المجلد | ما فيه |
|---|---|
| `postgres/` | قاعدة البيانات العاملة. يملكه مستخدم `postgres` في الحاوية |
| `kept/` | الصور والملفات. يملكها المعرّف ١٠٠٠١، وهو المستخدم الذي يعمل به Kept |
| `config/` | مفاتيح Kept ‏(`secrets.json`) وكلمات مرور قاعدة البيانات. يملكها المعرّف ١٠٠٠١ |
| `owner/` | كلمة مرور مالك قاعدة البيانات. لـ root وحده: لا تقرؤها عملية Kept أبدًا |
| `backup/kept.pgdump` | تفريغ لقاعدة البيانات يُكتب كلما توقفت الحاوية |

تبدأ الحاوية بصلاحيات root، فتعطي كل مجلد لصاحبه، ثم تشغّل Postgres وKept كلًّا بمستخدمه. ويبقى
المجلد نفسه لـ root: لا يستطيع غيره سرد محتواه.

## النسخ الاحتياطية

- **انسخ مجلد appdata احتياطيًا** والحاوية متوقفة، مثلًا بإضافة Appdata Backup في Unraid. فالتوقف
  يكتب `backup/kept.pgdump` أولًا، فتحمل النسخة الاحتياطية نسخة متّسقة من قاعدة البيانات وإن لم
  تكن الملفات العاملة كذلك.
- **الاستعادة:** أعد المجلد إلى مكانه وشغّل Kept. إن لم يكن فيه مجلد `postgres/` وكان في `backup/`
  تفريغ، يستعيد Kept قاعدة البيانات منه عند التشغيل، ويقول السجل
  `database restored from the backup`.
- **نسخ Kept الاحتياطية الليلية الخاصة** (الإدارة → النسخ الاحتياطية) غير مُعدّة في هذه الحاوية:
  تحتاج إلى تسجيل دخول مالك قاعدة البيانات، وKept العامل لا يملكه. انسخ مجلد appdata احتياطيًا.

## التحديثات

يتبع القالب الإصدار الرئيسي من Kept ‏(`kept-unraid:1`). حين يصدر إصدار جديد، يعرض تبويب **Docker**
تحديثًا لـ Kept: **apply update**. تتوقف الحاوية (وتكتب تفريغها)، وتبدأ الصورة الجديدة، ويرقّي Kept
قاعدة بياناته عند التشغيل.

## عنوان Kept

غيّره في القالب (أيقونة Kept، ثم **Edit**) ثم **Apply**. لتقديم Kept عبر https، ضع وكيلًا عكسيًا
أمام المنفذ ٨٠٨٠، واضبط **Kept's address** على عنوانه في https، و**Trusted reverse proxies** على
عنوان الوكيل كما يراه Kept ([خلف وكيل عكسي](/ar/install/reverse-proxy/)). الكاميرا وتثبيت تطبيق
الهاتف والإشعارات الفورية ومفاتيح المرور تحتاج إلى https
([Kept على شبكة منزلية](/ar/install/home-network/)).

## الإزالة

1. تبويب **Docker**، أيقونة Kept، ثم **Remove**. يبقى مجلد appdata.
2. لحذف البيانات أيضًا، احذف `/mnt/user/appdata/kept` من الطرفية أو من مدير ملفات. لا يمكن
   التراجع عن هذا: خذ نسخة احتياطية أولًا إن كنت قد تحتاجها.
