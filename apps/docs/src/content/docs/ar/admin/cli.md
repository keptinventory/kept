يحتوي الصورة على أمر `kept` للمشغّل: الترحيلات، وطريقة العودة إلى التسجيل الدخول عندما لا يستطيع
أحد، والمفاتيح، والنسخ الاحتياطي. `kept admin --help` يدرج كل شيء؛ كل أمر يتغيّر شيء ما يُدقّق،
ويُخبر شخص تلامس حسابه ببريده.

## التشغيل تحت Compose

معظم الأوامر تحتاج إلى دخول **المالك** (`KEPT_OWNER_DATABASE_URL`)، وهو الوحيد الذي يملكه الخدمة `migrate`
ذات التشغيل الفردي؛ الحاوية التي تقدّم الخدمة لا تملكه. مدخلها هو `kept`، إذن:

```sh
docker compose run --rm migrate admin <command>
```

نوعان من الأوامر تحتاجان إلى أحجام حاوية التقديم بدلًا من ذلك:

- `recovery-kit` تستقر المفاتيح من حاوية الإعدادات وترسلها حتى ولم تكن هناك قاعدة بيانات:
  `docker compose exec kept kept admin recovery-kit`. وبالإضافة إلى `KEPT_OWNER_DATABASE_URL` (في
  الأسفل) تحتوي أيضًا على مستودع النسخ الاحتياطي وكلمة مروره وبيانات اعتماده.
- `token create` تحتاج إلى المفاتيح وتسجيلات التقديم، التي يملكها الحاوية `kept`:
  `docker compose exec kept kept admin token create …` ([في الأسفل](#رمز-من-الخادم)).
- `rotate-key` و`backup` و`restore` و`export` تحتاج إلى المفاتيح أو الملفات بالإضافة إلى دخول
  المالك. أعطِ خدمة `kept` حق `KEPT_OWNER_DATABASE_URL` في `compose.override.yaml`
  ([كمثل لـ النسخ الاحتياطي](/ar/admin/backups/#التفعيل))، ثم شغّلها في حاوية واحدة:
  `docker compose run --rm --no-deps --entrypoint kept kept admin <command>`.

## الأوامر

| الأمر | ماذا يفعل |
|---|---|
| `kept migrate` | يُطبّق الترحيلات المعلقة مرة واحدة، تحت قفل في قاعدة البيانات (تُشغّل خدمة `migrate` كل بداية). |
| `kept admin setup-code` | يُصدر كود الإعداد الأول مرة أخرى، بينما الإعداد معلّق، ويُزيل قفل الحظر على مستوى النسخة. |
| `kept admin reset-password <login>` | كود إعادة تعيين كلمة المرور لمرة واحدة، صالح ساعة؛ يُسجّل الخروج من جميع الجلسات. |
| `kept admin disable-user <login>` / `enable-user <login>` | يمنع حسابًا من التسجيل الدخول (ويُنهي جلساته)، أو يسمح له مرة أخرى. |
| `kept admin transfer-ownership <locationId> <toUserId>` | يعطي الموقع لمسؤول آخر؛ يصبح المالك السابق مشرفًا عليه. |
| `kept admin recovery-kit [--format text\|html] [--out <file>]` | طقم الاسترداد الذي يُبقى بعيدًا عن الخادم: المفاتيح، ومستودع النسخ الاحتياطي وبيانات اعتماده، وخطوات الاسترداد. انظر [طقم الاسترداد](/ar/admin/recovery-kit/). |
| `kept admin token create --user <login> --scope read\|write --name <name>` | رمز شخصي لعملاء MCP و Home Assistant، يُطبع مرة واحدة؛ `--expires <days>`، `--location <id or name>` (يمكن تكراره)، `--confirm-cross-location`. منذ 1.3.0. انظر [رمزًا من الخادم](#رمز-من-الخادم). |
| `kept admin gen-key` | تطبع مفتاحًا جديدًا، ليضع `KEPT_SECRET_KEY` أو `KEPT_AUTH_SECRET` بنفسك. |
| `kept admin rotate-key` | يجعل مفتاحًا سريًا جديدًا هو الحالي ويغلّف كل الأسرار المخزنة مرة أخرى. `--resume` يُكمل السابق؛ `--drop <version>` يزيل مفتاحًا متقاعدًا لا يستخدمه أحد. |
| `kept admin backup` | يُنشئ الآن نسخًا احتياطيًا (لقطة restic)؛ `--list` يدرج اللقطات، وأي نسخ احتياطية أقدم قبل restic؛ `--accept-size` يقبل نسخة احتياطية أصغر بكثير كالوضع الجديد الطبيعي. انظر [النسخ الاحتياطي](/ar/admin/backups/). |
| `kept admin backup verify` | تتحقق من مستودع النسخ الاحتياطي؛ `--read-data <percent>` تقرأ أيضًا تلك جزءًا من البيانات؛ مع تخزين الملفات على S3، تتحقق من الملفات مقابل الـ bucket (`--all-files` لكل منها، وليس واحدًا من كل ٢٠). |
| `kept admin backup drill --into <database>` | تستعيد النسخة الاحتياطية الأحدث إلى قاعدة بيانات عشوائية **فارغ** وتتحقق منها: [التدريب الشهري](/ar/admin/restore/#التدريب-الشهري). |
| `kept admin backup unlock` | تزيل قفل restic القديم بعد تعطل؛ تُرفض أثناء تشغيل نسخة احتياطية. |
| `kept admin restore <snapshot>` | تستعيد لقطة (أو `latest`) إلى قاعدة بيانات **فارغ** وتتحقق منها؛ `--legacy <id>` تستعيد نسخة احتياطية قبل restic، لإصدار واحد. انظر [الاستعادة](/ar/admin/restore/). |
| `kept admin readable --out <dir>` | تكتب لكل مكان [النسخ القابلة للقراءة](/ar/admin/read-with-restic/) (HTML، CSV، ملفات) إلى مجلد؛ `--location <id>` لمكان واحد، و`--no-pdf` بدون ملفات المخزن. |
| `kept admin storage copy --to s3\|local` | تنسخ كل ملف إلى المتجر الآخر، وتتحقق من تجزئة كل منهما؛ `--dry-run` تحسب فقط. انظر [التبديل لتخزين الملفات](/ar/admin/storage/). |
| `kept admin storage verify --store s3\|local` | تتحقق من أن كل ملف يشير إليه قاعدة البيانات موجود في ذلك المتجر مع البايتات الصحيحة. |
| `kept admin export --out <dir>` | كل صف، خام، مع الأسرار المتبقية مختومة، وكل ملف، إلى مجلد جديد: مدخل الهروب، حساس مثل النسخ الاحتياطي. |
| `kept admin backfill-pdf-text` | تقرأ نص ملفات PDF التي رفعها قبل أن يقرأ Kept ملفات PDF، حتى يعثر البحث عليها. |
| `kept admin config` | تطبع [مرجع الإعدادات](/ar/reference/configuration/) لهذا الإصدار. |

يوجد `kept admin seed` للتطوير، ويرفض التشغيل في الإنتاج.

## رمز من الخادم

التطبيق يولد رموزًا شخصية فقط عبر HTTPS (الإعدادات → الربط ترفض الاتصال عبر `http` العادي).
يمكن لتطبيق Kept على الشبكة الرئيسية عبر `http` التوصّل بتطبيق ذكاء اصطناعي أو
[Home Assistant](/ar/users/home-assistant/): الشخص الذي يشغّل الخادم يولد الرمز هناك.
منذ 1.3.0:

```sh
docker compose exec kept kept admin token create \
  --user ibrahim@example.com --scope read --name "Home Assistant"
```

- `--user` هو الشخص الذي يتخذ عنه الرمز نواياه: بريده الإلكتروني، أو اسم مستخدم الحساب الإداري.
  يمكنه القيام بما يستطيعه، ولا أكثر.
- `--scope read` يقرأ فقط؛ `--scope write` يستطيع تغيير الأشياء أيضاً.
- بدون `--location`، يصل إلى كل المواقع التي ينتمي إليها الشخص، باستثناء تلك التي لا يستطيع:
  موقع يطلب المصادقة الثنائية (الرمز الذي صنع هنا ليس له عامل ثانٍ؛ اصنعه في الإعدادات → الربط،
  عبر HTTPS) وأيضًا، بالنسبة لرمز الكتابة، تلك التي يكون فيها مشاهدًا. كل من استثناه يُذكر.
  `--location` (معرف أو اسم، يمكن تكراره) يختارها بدلًا من ذلك.
- يتوقف رمز الكتابة عبر المواقع إذا اختلف أعضاؤها معًا مع تحذير، كما في التطبيق؛
  `--confirm-cross-location` يجعل ذلك على أي حال.
- `--expires <days>` يُنهيه بعد تلك الأيام؛ وبدونها، يعمل حتى يُلغى.

يطبع الرمز مرة واحدة، في السطر الذي يبدأ بـ `KEPT TOKEN:`، وعنوان خادم MCP. يحتفظ Kept
ببصمة منه. الشخص يراه في **الإعدادات → الربط**، حيث يمكنه إلغاءه، ويُخبره بالبريد.
